    A closer look at the architecture

    How a hierarchical Transformer processes bytes

    This example illustrates a common local encoder → global Transformer → local decoder design. Watch 16 input bytes get processed in three chunks, then produce byte-level outputs. The drawing is a conceptual animation, not a live model run or a measurement of compute.

    2. 2

    3. 3
      Local decoder

      Chunk-level information expands back to byte-level predictions, shown at the top of the diagram.

    What this playground does and doesn't show. Each rule set is compiled to a JavaScript regular expression and run live in your browser. The GPT-2 preset reproduces the published GPT-2 pattern exactly, and the real-tokenizer presets use the patterns from each model's Hugging Face tokenizer files (Kimi K2's rewritten in JavaScript syntax). Llama 2 and Gemma use SentencePiece, which has no regex, so their presets only approximate its splitting; GPT-4 style, Whitespace only and BERT-like are simplified approximations too. JavaScript and the Rust regex engine used by the tokenizers can differ in rare edge cases, such as which characters count as whitespace. Only the pre-tokenization step is shown: no BPE merges are applied, so the number of pre-tokens is only a lower bound on the final BPE token count.
